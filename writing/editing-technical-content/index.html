Editing technical instructions

How to check prerequisites, actions, and expected results in a procedure.

By John Kabeya

Check the starting point

List the permissions, files, and tools a reader needs before step one. If the procedure begins with “Open Settings,” name the application and the screen the reader should already be on. A prerequisite buried in step four can force someone to repeat the first three steps.

Give the reader a visible result

Consider “Export the report and make sure it worked.” In an illustrative rewrite, I’d say “Select Export CSV. When the download finishes, open the file and check that the first row contains Date, Item, and Quantity.” Verify those labels against the actual interface before using the wording.

Read through a branch

If the report can be empty, describe when that is expected and when it indicates a problem. Ask someone unfamiliar with the procedure to run it and mark where they had to infer a step.
