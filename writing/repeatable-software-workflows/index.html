Making a software workflow repeatable

How to document inputs, outputs, and verification for a small software project.

By John Kabeya

Record the starting conditions

Name the runtime version you tested, where commands should run, and how to obtain a small sample input. A three-row example often reveals more about the expected format than a paragraph of descriptions.

Describe the output

For a hypothetical CSV converter, the README could name examples/items.csv as the input and out/items.json as the output. It could then tell readers to expect three records, each with an ID and name. If the input has a header, state whether it counts as a record.

Run it twice

Run the workflow from a clean copy using only the documented steps. Run it again with the output already present. Document whether the rerun replaces, appends to, or rejects the file so the next person can decide whether it is safe.
